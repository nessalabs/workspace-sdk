The new pipe mode is distinct in launch identity while ordinary/PTY fingerprint bytes remain compatible; old claims default the optional mode flag to false. Both forms of one-shot launch stdin are refused before claims. The native owner retains stdin, makes one nonblocking write per request, reports only accepted prefix length (including zero under backpressure), and has no hidden replay queue. Input and real EOF execute in the same owner loop. Exact claim/mode validation precedes control effects; unknown ownership never establishes Closed. Input bytes remain transient/private and are omitted from debug output and persisted launch claims.

Closure and transport evidence are deliberately separate. Closed attests writer closure, not child consumption, success or process cleanup. A live owner definitively refuses later input. A fresh request during owner teardown may conservatively return Unknown or an unavailable-owner error; that does not reopen the endpoint or permit replay. Already-dispatched Unknown input must never be reclassified using later terminal/closed evidence. V2 explicitly drops the writer before terminal publication, and the bounded post-EOF fixture gate isolates the live-owner refusal assertion from teardown timing. The prior terminal method's empty-input behavior was restored, so this additive mode does not introduce that unrelated compatibility change.

The four native cases cover binary accepted-prefix round trip with real EOF and reconnect, admission/mode/workspace refusals and a golden legacy hash, actual full-pipe backpressure plus a stalled control client and cancellation, and lost/corrupt/oversized acknowledgements after actual dispatch with no input replay. The latter proves exact ABC output plus EOF even when an extra post-EOF refusal reply is lost. Shared control framing is bounded, processes at most one client per owner iteration and reuses the existing PTY framing rather than introducing a terminal engine. Socket lifetime is tied to owner scope.
