# PR #2 follow-up quality review

Reviewer: independent `performance_gate` agent. Scope: initial probe-state save
failure cleanup and durable publication of the live Vercel qualification
evidence/reproduction procedure. Root owns implementation and builds; the separate
adversarial reviewer owns regression tests. This reviewer makes no production

## Findings and required fixes

1. **P2, resolved:** `provider.open` creates an owned workspace before its initial
   durable state record. If that save fails, returning directly loses the only
   reconnect descriptor and strands the resources. Retain the opened backend,
   attempt bounded destruction, report cleanup failure separately, and preserve
   the original save error. Resolve the current executable before resource
   creation so another fallible operation cannot escape through the same gap.
   Destruction under failed storage is an attempt, not a guaranteed rollback;
   neither a non-Completed receipt nor timeout may be reported as success.
2. **P2, resolved:** ignored local `work/` files are insufficient durable evidence for
   a clean-checkout reviewer to audit the published PASS. Commit sanitized
   gate/phase/cleanup records and exact reproduction commands, with an index
   distinguishing original artifact digests from published/redacted digests.
   Retain original failed-gate context and label operator-transcribed privileged
   diagnostics accurately. Do not present sanitized bytes as the original raw
   artifact or silently broaden the qualified SDK/provider scope.

## Independent re-review

The fix keeps ownership at the creation boundary and uses the existing backend
`destroy` contract. It adds no new abstraction or provider dependency. Executable
resolution precedes acquisition; a failed first save attempts bounded destruction,
reports non-Completed/error/timeout outcomes honestly, and preserves the original
save error. This satisfies cohesion, dependency direction, and lifecycle ownership
without duplicating cleanup implementation. No remaining P1/P2 source finding.

The separate adversarial subprocess regression uses the actual OS file-size limit
and public example executable. RED failed with EFBIG and no deletion receipt
([red log](../evidence/vercel-linux-pty-artifacts/pr2-rollback-red.log), 0/1); GREEN passed with completed deletion and independently
absent owned directories ([green log](../evidence/vercel-linux-pty-artifacts/pr2-rollback-green.log), 1/1, 0.69s). The gate explicitly
builds the example in each feature configuration before executing its regression.

Audited all 27 historical artifacts against retained originals and the original
probe commit: every original and published SHA-256 matches its index. A separate
byte comparison confirmed exact identifier-only substitutions using one consistent
alias mapping. Numeric performance files, source/binary hashes, process identities,
failed/successful outcomes and command bodies remain intact. The original probe
source is preserved byte-for-byte and distinguished from the current rollback fix.
The failed privileged run and the operator-transcribed diagnostic provenance remain
visible. Reproduction uses three separate completed remote calls, obtains previous
controller PIDs from fresh results, applies the capability envelope to every call,
and requires finally-stop plus an independent stopped-state observation.

The artifact index and reproduction instructions are committed under
`docs/evidence/vercel-linux-pty-artifacts`; original private receipts remain local.
The published hashes are explicitly distinct from original unsanitized hashes.
